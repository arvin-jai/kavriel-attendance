# Pipeline (CI/CD)

How code gets from a branch to users. Everything runs on free tiers: GitHub Actions, Render (API),
Neon (PostgreSQL) and EAS (Android builds).

```
 feature branch ──PR──► CI (GitHub Actions) ──merge──► main
                          │ checks: lint · typecheck · format
                          │ backend-tests: unit + integration on Postgres 17 + migration drift
                          │ build: backend bundle + Android JS bundle
                          ▼
 main ──► Render auto-deploy (build → prisma migrate deploy → start) ──► https://<api>.onrender.com
      └─► (manual) EAS build: preview APK / production AAB ──► testers / Play Console

 scheduled: keep-warm ping (school hours) · nightly encrypted DB backup
```

## 1. Continuous integration: `.github/workflows/ci.yml`

Runs on every pull request and every push to `main`. Concurrent runs for the same ref are cancelled.

| Job             | What it does                                                                                                                                                                                                                                         | Fails when                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `checks`        | `npm ci`, `npm run lint`, `npm run typecheck` (all workspaces), `npm run format:check`                                                                                                                                                               | lint errors, type errors, unformatted files                 |
| `backend-tests` | Starts a `postgres:17` service; Vitest unit + integration projects. The integration global setup applies all migrations and the reference seed to the test DB (`TEST_DATABASE_URL`). Then `prisma migrate diff --from-config-datasource --to-schema` | any test fails; `schema.prisma` changed without a migration |
| `build`         | `npm run build:backend` (tsup bundle) and `expo export --platform android`                                                                                                                                                                           | bundling/import errors in either app                        |

Locally the same checks are:

```bash
npm run lint && npm run typecheck && npm run format:check && npm test && npm run build:backend
```

(`npm test` starts its own embedded PostgreSQL; no Docker or service needed.)

**Branch policy (recommended):** protect `main`, require the three CI jobs to pass, require one review,
squash-merge.

## 2. Backend deployment (Render)

- **Blueprint:** `render.yaml` (free web service, Singapore, Node 22).
- **Build:** `npm ci --include=dev && npm run build:backend`. `postinstall` runs `prisma generate`.
- **Start:** `npm run start:prod -w @kavriel/backend` → `prisma migrate deploy && node dist/server.js`.
  `migrate deploy` is idempotent and takes an advisory lock, so it is safe on every start.
- **Health check:** `GET /health` (no DB). `GET /health/ready` checks the database.
- **Trigger:** auto-deploy on push to `main`. In the Render dashboard set _Auto-Deploy_ to
  **"After CI checks pass"** if available on your plan; otherwise switch auto-deploy off and call a
  Render deploy hook from a workflow step after CI succeeds.

### Environment variables (Render dashboard)

| Variable                                | Source                            | Notes                                                                     |
| --------------------------------------- | --------------------------------- | ------------------------------------------------------------------------- |
| `DATABASE_URL`                          | Neon **pooled** connection string | `…-pooler…/kavriel?sslmode=require`                                       |
| `DIRECT_URL`                            | Neon **direct** connection string | used by `prisma migrate deploy` only                                      |
| `JWT_SECRET`                            | generated by Render               | ≥ 32 chars; rotating it signs everyone out                                |
| `QR_SIGNING_SECRET`                     | generated by Render               | must differ from `JWT_SECRET`; rotating it invalidates live QR codes only |
| `TEACHER_SIGNUP_CODE`                   | set by the school admin           | shared with teachers out-of-band                                          |
| `SCHOOL_TIMEZONE`                       | `Asia/Manila`                     | drives "today", start windows and report dates                            |
| `CORS_ORIGIN`                           | empty                             | add the admin web origin in Phase 3                                       |
| `NODE_ENV`, `NODE_VERSION`, `LOG_LEVEL` | blueprint                         |                                                                           |

Never commit secrets; `.env` files are gitignored and `.env.example` documents every variable.

## 3. Database migrations

| Where      | Command                                                                                                  | Rule                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Local      | `npx prisma migrate dev --name <change>` (in `apps/backend`)                                             | Commit the generated folder. For partial indexes/CHECKs use `--create-only`, edit the SQL, then `migrate dev`. |
| CI         | integration setup runs `prisma migrate deploy` on a fresh DB; drift check compares it to `schema.prisma` | a schema change without a migration fails CI                                                                   |
| Production | `prisma migrate deploy` at service start                                                                 | **Never** `migrate dev`, `migrate reset` or `db push` against production                                       |

Destructive changes use **expand → migrate → contract** over two releases (add new column/table, backfill,
switch code, drop the old one in a later release), so a rollback of the app never meets a missing column.

## 4. Mobile releases (EAS)

- Profiles in `apps/mobile/eas.json`:
  - `development`: dev client APK, API at the emulator host (`10.0.2.2`).
  - `preview`: internal-distribution APK against the Render API. Use this for pilots.
  - `production`: Play Store AAB with auto-incremented version code.
- **One-time setup:** `npx eas-cli login`, `npx eas-cli init` in `apps/mobile` (adds the project id to
  `app.json`), then add an `EXPO_TOKEN` repository secret.
- **Build:** run the **Mobile build (EAS)** workflow (`workflow_dispatch`, choose profile), or locally
  `npx eas-cli build -p android --profile preview`.
- `EXPO_PUBLIC_API_URL` is baked in at build time per profile. It is the only config in the app, and it isn't secret.
- The free EAS tier has a monthly build quota; local builds (`--local`) are the fallback.

## 5. Scheduled workflows

| Workflow        | Schedule                              | Purpose                                                                               | Needs                                                                           |
| --------------- | ------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `keep-warm.yml` | every 10 min, Mon–Sat 06:00–18:00 PHT | avoids a cold start before class; sleeps otherwise to stay inside free instance hours | repo variable `API_HEALTH_URL` (e.g. `https://kavriel-attendance.onrender.com/health`) |
| `backup.yml`    | daily 02:00 PHT                       | `pg_dump` (PostgreSQL 17 client) → encrypted with `age` → 30-day artifact             | secrets `DIRECT_URL`, `AGE_PUBLIC_KEY`                                          |

Both are no-ops until configured.

## 7. Rollback

- **API:** Render → Deploys → _Rollback_ to the previous deploy. Because migrations are additive
  (expand/contract), the previous build runs against the newer schema.
- **Database:** restore the latest encrypted backup into a new Neon branch, verify, then repoint
  `DATABASE_URL`/`DIRECT_URL` (see HANDOFF.md → Backup & restore).
- **Mobile:** publish the previous build (or halt the staged rollout in Play Console).
